오프라인 업무 프로그램 기반 설계

사업비 관리 프로그램(v1.0.2)에서 쓴 업무와 상관없는 바탕만 정리했습니다. 다른 프로그램을 만들 때 이 문서를 그대로 주고 "이 기반으로 만들어 줘"라고 하면 됩니다.

1. 전제 · 실행 환경

  • 설치 · 서버 · 인터넷 없음. 보안망 안에서 HTML 만 허용되므로 index.html 을 크롬(또는 엣지)으로 더블클릭해서 엽니다 (주소가 file://).
  • 자바스크립트는 일반 <script> 태그로 불러옵니다. type="module" · import · fetch() 는 file:// 에서 막히므로 쓰지 않습니다.
  • 외부 라이브러리는 인터넷 주소(CDN)가 아니라 파일로 같이 넣습니다 (예: 엑셀 읽고 쓰기 vendor/xlsx.full.min.js = SheetJS).
  • 앱 코드는 파일마다 (function (root) { "use strict"; ... root.Store = {...}; })(this); 처럼 감싸고, 밖에 내놓을 것만 전역 이름 하나로 내놓습니다.
  • 패키지에 .txt 파일을 넣지 않습니다 (보안망 반입 문제). 사용 설명서도 JS 안에 넣어 프로그램 안에서 엽니다.
파일맡은 일
index.html화면 뼈대 · 스크립트 불러오기 (순서: vendor → 기반 → 계산 → 설명서 → 앱)
js/store.js폴더 연결 · 파일 읽기/쓰기 · 백업 · 형식 검사 (업무와 무관한 부분은 거의 그대로 재사용 가능)
js/calc.js순수 계산 (화면 · 파일과 분리 → 따로 검사하기 쉬움)
js/app.js화면 · 저장 흐름 · 실행 취소 · 팝업
js/help.js사용 설명서 (window.HELP = [[제목, [줄...]], ...])
js/testdata.js테스트용 가짜 자료 — 배포판에서는 빠짐

2. 폴더 구성 — 프로그램과 자료를 나눈다

프로그램이름\ program\ ← 프로그램. 업데이트 때 이 폴더만 통째로 교체 index.html css\ js\ vendor\ storage\ ← 자료. [폴더 연결]에서 이 폴더를 고름. 업데이트 때 건드리지 않음 data\ ← 진짜 자료 (엑셀) backup\ ← 저장할 때마다 이전 파일 보관 (원본 자료)\ ← 사람이 넣는 입력 파일 (예: 더존원본\2026\)
왜: 프로그램 폴더를 지우고 새로 넣어도 자료가 안전합니다. 백업은 storage 폴더만 복사하면 끝.
  • 사용자가 실수로 program 폴더를 자료 폴더로 고르면 경고합니다 (그 안에 index.html 과 js 가 있으면 프로그램 폴더로 판단).
  • 같은 위치에 새 program 을 넣으면 즐겨찾기 · 폴더 연결 · 화면 설정이 그대로 이어집니다 (크롬은 file:// 페이지끼리 저장소를 같이 씀).

3. 폴더 연결 (File System Access API)

  1. 처음: 버튼 클릭 → showDirectoryPicker({ id: "앱이름", mode: "readwrite" }) → 받은 폴더 핸들을 IndexedDB 에 저장.
  2. 다음에 켤 때: IndexedDB 에서 핸들을 꺼내 queryPermission({mode:"readwrite"})
    • granted → 바로 열기
    • 그 외 → "이 폴더 계속 사용" 버튼 → requestPermission() (반드시 버튼 클릭 안에서 불러야 함 — 크롬 규칙)
    • 핸들 없음 → "폴더 연결" 화면
  3. 못 읽으면 (폴더를 옮기거나 지움) 오류 메시지만 띄우지 말고 다시 고르기 화면을 보여 줍니다.
  4. 새 폴더면 기본 설정 파일을 그 자리에서 바로 저장합니다 (안 하면 "저장 안 함"을 고를 때 기본 파일이 안 생기는 구멍이 생김).
// IndexedDB 에 폴더 핸들 기억 (핵심만)
var DB_NAME = "앱이름-app", DB_STORE = "kv", KEY_DIR = "dataDir";
function idb() { return new Promise(function (ok, fail) {
  var q = indexedDB.open(DB_NAME, 1);
  q.onupgradeneeded = function () { q.result.createObjectStore(DB_STORE); };
  q.onsuccess = function () { ok(q.result); }; q.onerror = function () { fail(q.error); };
}); }
// restore(): "ready" | "needPermission" | "none"
function restore() {
  return idbGet(KEY_DIR).then(function (h) {
    if (!h) return "none";
    dir = h;
    return h.queryPermission({ mode: "readwrite" }).then(function (p) { return p === "granted" ? "ready" : "needPermission"; });
  }).catch(function () { return "none"; });
}
자동 점검용: 주소 끝에 #opfs 를 붙이면 브라우저 내부 저장소(OPFS, navigator.storage.getDirectory())를 폴더처럼 씁니다. 폴더 고르기 창 없이 자동 테스트가 돌아갑니다.

4. 자료 파일 형식 — 사람이 열어 볼 수 있는 엑셀

  • 자료는 .xlsx 로 저장합니다. 비상시 엑셀로 열어 확인할 수 있고, 프로그램이 망가져도 자료는 남습니다.
  • 모든 파일에 "정보" 시트: 저장시각 · 프로그램 · 형식버전 · 설정값. (12장 참고)
  • 공통 기준(분류 등)은 한 파일, 연도(기간)별 자료는 연도마다 한 파일 → 파일 하나가 망가져도 피해가 작음.
  • 항목끼리는 이름이 아니라 ID로 연결합니다 (이름을 바꿔도 연결이 안 끊김). ID 는 G1 · M12 · A305 처럼 종류 + 일련번호.
  • 큰 자료(예: 전표 몇 만 줄)는 별도 파일로 분리 (집행_2026.xlsx + 집행_2026_내역.xlsx) → 자주 바뀌는 작은 파일 저장이 빨라짐.
  • 예전 형식도 읽게 둡니다 (열 이름이 없으면 옛 형식으로 해석).
규칙: 사용자가 data 파일을 직접 고치지 않게 안내합니다. 그래도 고쳤다면 9장의 방식으로 막습니다.

5. 파일 쓰기 — 가장 중요한 4가지

① 저장할 내용은 "부른 그 순간" 것으로 굳힌다

저장 함수가 나중에 실행될 때 현재 상태 변수를 읽으면, 그 사이 연도를 바꾼 경우 새 연도의 빈 내용이 옛 파일에 써지는 사고가 납니다 (실제로 겪음). 저장을 부르는 순간 바이트(또는 상태 객체 참조)를 만들어 넘깁니다.

② 같은 파일은 차례대로 (파일별 줄 세우기)

앞 저장이 늦게 끝나 새 내용을 덮어쓰는 일을 막습니다. 앞 저장이 실패해도 다음 차례는 진행.

③ 쓰기 직전 "밖에서 바뀌었나" 확인

읽을 때 파일 수정 시각(lastModified)을 기억해 두고, 쓰기 직전에 다르면 쓰지 않고 멈춥니다 (9장).

④ 보기 전용 창은 아예 쓰지 않는다

var KNOWN = {}, READONLY = false, WQ = {};
function readFile(folder, name, noTrack) {      // noTrack: 백업 읽기 등은 기억하지 않음
  return sub(folder).then(function (d) { return d.getFileHandle(name); })
    .then(function (fh) { return fh.getFile(); })
    .then(function (f) { if (folder === "data" && !noTrack) KNOWN[name] = f.lastModified; return f.arrayBuffer(); });
}
function writeFile(folder, name, data) {
  if (READONLY) return Promise.reject({ name: "ReadOnly" });
  var key = folder + "/" + name, prev = WQ[key] || Promise.resolve();
  var job = prev.catch(function () {}).then(function () { return writeNow(folder, name, data); });
  WQ[key] = job.catch(function () {});
  return job;
}
function writeNow(folder, name, data) {
  return sub(folder).then(function (d) {
    var check = folder !== "data" ? Promise.resolve() : d.getFileHandle(name).then(function (fh) { return fh.getFile(); })
      .then(function (f) { if (KNOWN[name] !== undefined && f.lastModified !== KNOWN[name]) throw { name: "ExternalChange", file: name }; },
            function (e) { if (e && e.name === "ExternalChange") throw e; /* 파일 없음 → 새로 */ });
    return check.then(function () { return d.getFileHandle(name, { create: true }); }).then(function (fh) {
      return fh.createWritable().then(function (w) { return w.write(data).then(function () { return w.close(); }); })
        .then(function () { return folder === "data" ? fh.getFile().then(function (f) { KNOWN[name] = f.lastModified; }) : null; });
    });
  });
}
function idle() { return Promise.all(Object.keys(WQ).map(function (k) { return WQ[k]; })); } // 모든 저장 끝날 때까지
createWritable() 은 임시 파일에 쓰다가 close() 때 한 번에 바꿔치기하므로, 쓰다가 꺼져도 원래 파일이 반쯤 깨지지 않습니다.

6. 백업

  • data 파일을 덮어쓰기 직전에 지금 파일을 backup\파일이름_YYYYMMDD_HHMMSS.xlsx 로 복사.
  • 같은 파일은 30분에 한 번만 (자동 저장마다 백업이 쌓이지 않게). 위험한 작업(되돌리기 · 덮어쓰기) 전에는 무조건.
  • 파일별 최근 30개만 남기고 오래된 것부터 지움.
  • 백업을 읽을 때는 noTrack 으로 읽어 "밖에서 바뀜" 판단을 흐리지 않게.
var BACKUP_KEEP = 30, BACKUP_EVERY_MS = 30 * 60000, lastBackup = {};
function backupIfDue(name, force) {
  var now = Date.now();
  if (!force && lastBackup[name] && now - lastBackup[name] < BACKUP_EVERY_MS) return Promise.resolve(false);
  var base = name.replace(/\.xlsx$/, "");
  return readFile("data", name, true).then(function (buf) {
    return writeFile("backup", base + "_" + stamp(null, true) + ".xlsx", buf).then(function () { lastBackup[name] = now; return prune(base + "_"); });
  }, function () { return false; }); // 아직 파일이 없으면 백업할 것도 없음
}

7. 저장 3가지 + 상태 표시

방식언제구현
① 고치면 자동무엇이든 바꾸면 0.7초 뒤변경 함수마다 scheduleSave() (타이머를 다시 걸어 연달아 고치면 한 번만 저장)
② 주기 저장5분마다열린 모든 자료 저장 (팝업이 떠 있거나 작업 중이면 건너뜀)
③ 수동 저장제목 줄 오른쪽 위 [💾 저장] · Ctrl+S즉시 전부 저장
  • 파일별 상태를 따로 둡니다: SVS[파일이름] = { st: "saving" | "ok" | "err", at, err, retry }.
  • 제목 줄 표시: 저장 중 · 저장됨(시각) · 저장 실패(빨강, 어느 파일인지). 실패 표시를 누르면 실패한 파일만 다시 저장 (폴더 허용이 풀렸으면 먼저 다시 허용).
  • "저장 안 된 것이 있나"는 한 함수로: 저장 대기 중 · 공통 파일 바뀜 · 저장 줄에 남은 것 · 저장 중/실패 파일.
  • 크롬을 그냥 닫을 때 뜨는 확인창은 믿을 수 없으므로(안 뜨는 경우 많음) 자주 자동 저장하는 쪽으로 해결.
function scheduleSave() { savePending = true; renderSave(); clearTimeout(saveTimer); saveTimer = setTimeout(doSave, 700); }
function hasUnsaved() { return savePending || masterDirty || Object.keys(XQ).length > 0 ||
  Object.keys(SVS).some(function (k) { return SVS[k].st === "saving" || SVS[k].st === "err"; }); }
function flushSave() { /* 대기 중인 저장을 지금 실행 */ return Promise.all([savePending || masterDirty ? doSave() : null, xFlush()]).then(Store.idle); }

8. "저장할까요?" · 켰을 때로 되돌리기

  • 화면 전체 자료를 새로 띄우는 동작(연도 바꾸기 · 다시 불러오기 · 새 연도 · 폴더 바꾸기) 전에 저장 안 된 것이 있으면 묻습니다: 저장하고 계속 / 저장 안 하고 계속 / 취소. 없으면 묻지 않고 대기 중 저장만 마친 뒤 진행.
  • "막 만지다 일부러 저장 안 하고 싶을 때"를 위해: 프로그램을 켜고 처음 연 순간의 파일 바이트를 메모리에 보관 → 파일 탭 [켰을 때로 되돌리기] (지금 파일은 먼저 backup 에).
// 처음 여는 파일은 원본 바이트를 한 번만 챙겨 둠
function keepStart(names) {
  var todo = names.filter(function (n) { return !(n in START.files); });
  todo.forEach(function (n) { START.files[n] = null; });
  return Promise.all(todo.map(function (n) { return Store.readRaw(n).then(function (b) { START.files[n] = b; }); }));
}

9. 프로그램 밖에서 바뀐 파일

  • 쓰기 직전 수정 시각이 기억과 다르면 ExternalChange 로 멈추고 묻습니다: 다시 불러오기(밖의 변경을 받아들임) / 덮어쓰기(밖에서 고친 파일은 backup 에 먼저 남김).
  • "새 파일인데 시각이 다르다" 같은 애매한 경우로 경고를 띄우지 않습니다 (헛경보는 사용자가 경고를 무시하게 만듦).

10. 같은 프로그램을 창 두 개로 열 때

  • localStorage 에 { id: 창ID, ts: 시각 } 를 2초마다 갱신(심장 박동). 다른 창의 기록이 5초 안이면 나는 보기 전용.
  • 보기 전용 창: 노란 띠 "이 창은 보기 전용" + [이 창에서 저장하기] 버튼. 파일 쓰기는 기반에서 거부.
  • 먼저 창이 닫히면 남은 창이 자동으로 저장 가능해지고 "최신 내용을 다시 불러오세요" 안내.
  • 창을 닫을 때(pagehide) 내 기록을 지움.
function startOwner() {
  var o = owner();
  if (o && o.id !== WIN_ID && Date.now() - o.ts < 5000) setReadOnly(true); else { claimOwner(); setReadOnly(false); }
  setInterval(function () {
    var cur = owner();
    if (!Store.readOnly()) { if (cur && cur.id !== WIN_ID && Date.now() - cur.ts < 5000) setReadOnly(true); else claimOwner(); }
    else if (!cur || Date.now() - cur.ts > 5000) { claimOwner(); setReadOnly(false); /* 안내 */ }
  }, 2000);
}
공유폴더에서 여러 사람이 동시에 쓰는 문제는 이것으로 해결되지 않습니다 (같은 PC 의 창끼리만). 보류 과제.

11. 실행 취소 · 다시 실행

  • 바꾸기 전 상태 전체를 JSON 문자열로 찍어 둠(스냅숏). 칸 하나 단위로 되돌리는 것보다 단순하고 실수가 적습니다.
  • 모든 변경은 한 함수 change(fn, 설명) 를 거치게 → 자동으로 스냅숏 · 기록 · 화면 갱신 · 자동 저장.
  • 최근 100번. 각 기록에 설명 · 시각 → [▾ 기록] 목록에서 골라 그 시점까지 한 번에 되돌리기.
  • 되돌린 뒤에도 자동 저장이 돌므로 파일과 화면이 어긋나지 않음.
  • 되돌릴 수 없는 작업(외부 자료 반영 등)은 따로 표시하고, 다른 자료로 바꾸면 기록을 비움.
function pushUndo(label) {
  undoStack.push({ s: snapshot(), label: label || "변경", t: 시각 });
  if (undoStack.length > 100) undoStack.shift();
  redoStack = [];
}
function change(fn, logMsg) { pushUndo(logMsg); fn(); addLog(logMsg); renderAll(); scheduleSave(); }
function undo(n) { /* n번: 지금을 redo 에 넣고 undoStack 에서 꺼내 restoreSnap */ }

12. 버전 · 업데이트 보호

  • APP_VER(예: "1.0.2") — 첫 화면 · 사용 설명서 제목에 표시. 배포할 때마다 올림.
  • FORMAT_VER(파일 구조 번호) — 파일의 "정보" 시트에 기록. 파일 구조를 바꿀 때만 올림.
  • 읽을 때 파일의 형식 번호가 프로그램보다 크면 = 옛 프로그램이 새 자료를 연 것 → 열지 않고 "프로그램을 새 버전으로 바꾸세요" 화면 (덮어써서 자료가 망가지는 것을 막음).
  • 새 프로그램은 옛 형식을 계속 읽을 수 있게 유지.
function newerCheck(wb, name) {
  var v = 0;
  rowsOf(wb, "정보").forEach(function (r) { if (str(r["항목"]) === "형식버전") v = Number(r["값"]) || 0; });
  if (v > FORMAT_VER) { var e = new Error(name + " 은 더 새 프로그램으로 저장된 파일입니다"); e.name = "NewerFormat"; throw e; }
}

13. 화면 공통

  • 첫 화면(cover) 상태별: 폴더 연결 전 / 허용 필요 / 자료 없음(새로 만들기) / 못 읽음(다시 고르기) / 새 버전 필요 / 브라우저 미지원.
  • 팝업: 한 함수 openDialog({title, body, okText, onOk, onClose, confirmClose}). 모든 팝업 이동 · 크기 조절 · 최대화, 종류별 마지막 위치 · 크기 기억. Esc = 닫기. 입력을 고친 팝업은 Esc · ✕ 로 닫을 때 버릴지 묻기.
  • 알림(toast): 화면 아래 잠깐 뜨는 메시지. 오류는 빨강 · 길게.
  • 리본 메뉴(엑셀처럼 탭 + 묶음), 제목 줄에 저장 상태 + 저장 버튼.
  • 사용 설명서를 프로그램 안에 (검색 가능). 개발판 전용 줄은 "@test " 로 시작해 배포판에서 숨김.
  • 작업 중(BUSY)에는 화면 전환 · 자동 저장을 잠시 멈춤.
  • 비동기 결과가 늦게 도착했을 때 그 팝업이 이미 닫혔으면 버리기 (안 하면 화면 요소를 못 찾아 오류).

17. 새 프로그램 만들 때 체크리스트

  • program / storage 폴더 분리, zip 경로 영문, .txt 없음
  • 일반 script 태그 + 파일마다 즉시 실행 함수, 외부 라이브러리는 vendor 에 파일로
  • 폴더 연결: 핸들 IndexedDB 저장 · 허용 다시 묻기(버튼 안) · 못 읽으면 다시 고르기 · 프로그램 폴더 경고
  • 자료는 엑셀, 모든 파일에 "정보" 시트(형식버전 · 저장시각), 항목은 ID 로 연결
  • 쓰기: 내용 굳히기 · 파일별 차례 · 밖에서 바뀜 확인 · 보기 전용 거부
  • 백업: 덮어쓰기 직전, 30분에 한 번, 파일별 30개
  • 저장 3가지(자동 0.7초 · 5분 주기 · 버튼/Ctrl+S) + 파일별 상태 표시 + 실패 시 다시 저장
  • 자료 바꾸기 전 "저장할까요?" (저장하고 계속 / 안 하고 계속 / 취소)
  • 켰을 때로 되돌리기 (처음 연 파일 바이트 보관)
  • 창 두 개 막기 (2초 심장 박동, 5초 기준, 보기 전용 띠)
  • 실행 취소 100번 + 기록 목록에서 골라 되돌리기, 모든 변경은 change() 한 곳으로
  • APP_VER 표시 · FORMAT_VER 로 옛 프로그램이 새 자료 못 열게
  • 팝업 공통(이동 · 크기 · 기억 · Esc · 고친 것 버릴지 묻기), 첫 화면 상태별 안내
  • 개인 화면 설정만 localStorage (앱 이름 앞에 붙이기, try/catch)
  • 사용 설명서는 프로그램 안에
  • 테스트 데이터 파일 분리 → 배포 스크립트가 자동으로 뺌, #opfs 자동 테스트
