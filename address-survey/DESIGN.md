# 직원 거주지 주소 취합 사이트 — 설계서 (v0.1)

직원이 휴대폰으로 거주지 주소와 발령 희망을 직접 입력함. 서버가 전국 센터까지의 거리를 계산함. 결과는 회사 보안망으로 반입해 오프라인 발령 프로그램에서 씀.

---

## 0. 확정 사항

| 항목 | 결정 |
|---|---|
| 위치 | `hr-note` 저장소 안 `address-survey/` 폴더. 브랜치에서 작업. Vercel은 별도 프로젝트(Root Directory = `address-survey`) |
| 서버 | Vercel 함수(`/api/*`) + Neon(Postgres). hr-note 기존 백엔드(Railway)와 분리 |
| DB | 이 조사 전용 Neon 프로젝트(또는 전용 DB). 파기할 때 다른 자료와 섞이지 않게 함 |
| API 연결 | 담당자가 직접 연결함(카카오 주소검색·좌표, 네이버 길찾기). 키는 Vercel 환경변수로 둠 |
| 국외 저장 | Neon 국내 리전 없음 → 동의서에 국외 저장 명시. "조사 완료 후 서버 자료 즉시 파기" 명시 |
| 본인 확인 | **성명 + 생년월일**(사번 안 씀). 휴대폰 인증 없음 |
| 비밀번호 분실 | 관리자 초기화 → 처음 단계부터 다시 |
| 실제 주소 | **필요함** → 해시가 아니라 **암호화 저장**. 담당자만 풀 수 있음 |
| 미제출자 확인 | 담당자가 성명·생년월일 명단을 올림 → 제출 여부 대조 |
| 비밀키 | 담당자 1명만 보관 |
| 자료 삭제 | 관리자 화면 **[전체 파기]** 버튼 → 서버 자료 전부 삭제 |
| 2025년 주소 | 작년 자료는 안 올림. 직원이 "달라짐" 체크 후 이전 주소를 직접 입력 |
| 희망발령지 | **센터** 선택지에서 1·2·3순위 |
| 희망 사유 | 드롭다운 구분값 선택 + 서술 입력 |
| 거리 기준 | 네이버 길찾기 **최적 경로(traoptimal)** |
| 거리 표시 | **전 센터 모두 표시**. 같은 주소에 있는 조직은 한 번만 계산하고 결과는 조직별로 전부 출력 |
| 이사 예정지 | "발령 기준지" 체크해도 **산출은 현 거주지 기준**. 화면에 안내 문구 표시 |
| 제출 후 수정 | **불가**. "수정이 필요하면 손사지원파트 신이삭 수석에게 연락" 안내. 관리자가 [재작성 허용] 가능 |
| 마감·안내 | 사이트에서 안 함(사내 메신저로 따로 안내) |

## 1. 전체 흐름

```
[담당자] 조직 주소 업로드 ─┐
[담당자] 명단(성명·생년월일) 업로드 ─┤
                                  ▼
[직원 휴대폰] 링크 접속 → 입력 → 산출 → 제출
                                  ▼
[담당자 PC] 진행 현황 · 미제출 대조 → 내려받기(비밀키로 복호화) → 보안망 반입
                                  ▼
[담당자] 전체 파기
```

## 2. 직원 화면 (모바일, 한 화면 한 단계, 위에 진행 막대)

| 단계 | 화면 | 동작 |
|---|---|---|
| ① 본인 확인 | 성명 · 생년월일(8자리) | 올려 둔 명단과 맞아야 통과함. 처음이면 ②로, 비번이 있으면 비번 입력으로 감 |
| ② 개인정보 동의 | 동의서 전문 + [동의] | 동의 시각과 문구 버전을 저장함. 미동의 시 종료 |
| ③ 비밀번호 설정 | 비번 + 확인 (숫자 6자리 이상 등) | 다음 접속부터 성명 · 생년월일 · 비번으로 들어옴 |
| ④ 현 거주지 | 카카오 주소검색 → 도로명 선택 + 상세주소 | |
| ⑤ 이전 주소 | ☐ 2025년 주소와 달라짐 → 체크하면 이전 주소(주소검색 + 상세) | |
| ⑥ 이사 예정 | ☐ 이사 예정 있음 → 예정월(년 · 월) + 예정지(**동까지만**: 주소검색에서 시도 · 시군구 · 읍면동만 저장) + ☐ 발령 기준지로 삼음 | 기준지 체크 시 안내: "거리 산출은 **현 거주지 기준**으로 함. 이사 예정지는 발령 시 참고함" |
| ⑦ 거리 산출 | [산출] → 전 센터 거리표(가까운 순). 센터명 · 부서 · km · 예상 분. 50km 이상은 "사택 대상" 표시 | 다시 산출 가능(주소를 바꾼 경우) |
| ⑧ 발령 희망 | 희망 있음 / 없음 → 있으면 구분(드롭다운) + 서술 | |
| ⑨ 희망발령지 | 1 · 2 · 3순위 센터 선택(중복 불가). 각 센터 옆에 ⑦의 거리를 표시 | 희망 있음일 때만 |
| ⑩ 확인 · 제출 | 전체 요약 → [최종 제출] → 완료 화면 | 제출 후 잠김. "수정이 필요하면 손사지원파트 신이삭 수석에게 연락" |

- 제출 전에는 단계마다 서버에 임시저장함(암호화 상태로). 나갔다 들어와도 이어서 할 수 있음.
- 제출 후 다시 로그인하면 "제출 완료 · 제출일시"와 안내 문구만 보임.

### 희망 사유 구분값 (초안 · 관리자 설정에서 수정)
육아 · 간병 · 통근 거리 · 이사 · 건강 · 배우자 근무지 · 경력 개발 · 기타

## 3. 관리자 화면 (PC)

| 메뉴 | 내용 |
|---|---|
| 로그인 | 관리자 계정(아이디 · 비번) |
| 조직 주소 | 엑셀 업로드(조직코드 · 부서 · 센터명 · 주소). 주소가 같은 조직끼리 자동으로 묶어 좌표는 한 번만 받음 |
| 명단 | 엑셀 업로드(성명 · 생년월일, 선택: 부서). 같은 성명+생년월일이 있으면 경고 |
| 진행 현황 | 전체 · 부서별 제출 / 작성 중 / 미접속 수 |
| 미제출 대조 | 비밀키 파일을 불러와야 이름이 보임 → 미제출자 명단 표시 · 복사 |
| 개별 처리 | 비번 초기화, [재작성 허용](제출 잠금 해제), 거리 재산출 |
| 설정 | 동의서 문구 · 버전, 희망 사유 구분값, 사택 기준 거리(50km), 접수 열기/닫기 |
| 내려받기 | 비밀키로 복호화 → 엑셀 생성(아래 5장) |
| 전체 파기 | "파기" 입력 후 실행 → 직원 · 주소 · 거리 · 희망 · 로그 전부 삭제. 조직 주소와 설정은 남길지 선택 |

## 4. 개인정보 처리 · 보안

### 4-1. 방식
| 구분 | 방식 | 서버가 원문을 볼 수 있나 |
|---|---|---|
| 로그인 조회 키 | **HMAC-SHA256(정규화 성명 + 생년월일, 서버 비밀값)** | 불가 (대조만 가능) |
| 비밀번호 | **bcrypt** | 불가 |
| 성명 · 생년월일 · 주소 · 희망 사유 서술 | **공개키 암호화** (RSA-OAEP + AES-256-GCM) | **불가.** 서버에는 공개키만 있음. 푸는 개인키는 담당자만 가짐 |
| 거리값 · 센터코드 · 체크 여부 · 구분값 | 그대로 저장 | 개인 식별 정보 아님 |

- **산출할 때만** 서버 메모리에서 주소 원문을 잠깐 써서 카카오 좌표 → 네이버 거리를 계산함. 끝나면 버림. 좌표는 저장 안 함.
- 서버 로그에 주소 · 성명이 남지 않게 함(요청 본문 로그 금지).
- 담당자 개인키는 파일(비밀번호로 잠금)로 보관함. **잃어버리면 자료를 못 엶** → 반입 전까지 보관 주의.
- 복호화와 엑셀 생성은 **관리자 브라우저 안에서만** 함. 개인키는 서버로 안 보냄.

### 4-2. 기타
- HTTPS만 허용. 본인 확인 · 비번 5회 틀리면 잠금(관리자 초기화). 요청 횟수 제한.
- 관리자 비번은 bcrypt로 저장하고 세션은 짧게 둠.
- Vercel 환경변수: `DATABASE_URL`, `HMAC_SECRET`, `PUBLIC_KEY`, `KAKAO_REST_KEY`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `ADMIN_*`, `JWT_SECRET`

### 4-3. 동의서에 들어갈 내용 (초안 항목)
1. 수집 항목: 성명, 생년월일, 현 거주지 주소, 2025년 주소(변경 시), 이사 예정월 · 예정지(동 단위), 발령 희망 여부 · 사유 · 희망 센터
2. 목적: 정기 인사발령 및 사택 배정 검토
3. **처리 위치: 해외 클라우드 서버(Neon, 리전명 기재)에 암호화하여 저장**
4. 처리 위탁: 주소 검색 · 좌표(카카오), 거리 계산(네이버)
5. **보유 · 파기: 조사 완료 후 서버 자료 즉시 파기.** 자료는 회사 보안망 내로 옮겨 인사 업무에 사용함
6. 동의 거부권과 거부 시 불이익(거리 자동 산출 불가 등)

## 5. 거리 계산

- 출발: 현 거주지 좌표 / 도착: **주소가 다른 조직 위치마다 1번** 계산 → 같은 주소 조직들에 같은 결과를 붙임
- 옵션: 네이버 Directions 5 `traoptimal`. 결과는 km(소수 1자리) · 예상 분
- 동시 호출: 묶어서 병렬 처리(예: 10건씩). 실패한 곳만 다시 시도
- 저장: (직원, 조직위치, km, 분, 옵션, 산출일시)
- 주소를 못 찾거나 경로가 없으면 "산출 실패" 표시 → 관리자가 재산출

## 6. 자료 구조 (Neon)

| 테이블 | 주요 칸 |
|---|---|
| `org_sites` | site_id, 정규화 주소, 좌표 (조직 위치. 개인정보 아님) |
| `orgs` | org_code, 부서, 센터명, site_id, 표시순서 |
| `roster` | id, key_hmac(성명+생년월일), enc_identity(성명 · 생년월일 암호문), dept(선택) |
| `accounts` | roster_id, pw_hash, 실패횟수, 잠금여부, 마지막접속 |
| `consents` | roster_id, 문구버전, 동의일시 |
| `responses` | roster_id, enc_payload(주소 3종 · 사유 서술 암호문), prev_changed, move_planned, move_month, move_as_base, wish(Y/N), reason_code, wish1/2/3(org_code), status(작성 중/제출), submitted_at |
| `distances` | roster_id, site_id, km, min, option, calc_at |
| `settings` | 동의서 문구 · 버전, 사유 구분값, 사택 기준 km, 접수 열림 |
| `admins` | id, pw_hash |
| `audit` | 시각, 행위(로그인 · 내려받기 · 초기화 · 파기), 대상 roster_id (이름 · 주소 없음) |

## 7. 내려받기 엑셀 (보안망 반입용)

| 시트 | 내용 |
|---|---|
| 정보 | 생성일시, 거리 옵션(traoptimal), 사택 기준 km, 형식버전, 동의서 버전 |
| 조직 | 조직코드, 부서, 센터명, 주소 |
| 응답 | 성명, 생년월일, 현 주소, 2025 주소 변경 여부 · 이전 주소, 이사 예정 · 예정월 · 예정지(동) · 기준지 여부, 희망 여부 · 구분 · 서술, 희망 1 · 2 · 3, 제출일시 |
| 거리 | 행 = 직원, 열 = 조직(전체), 값 = km |
| 소요시간 | 같은 형태, 값 = 분 |
| 사택대상 | 직원 × 조직 중 50km 이상 |
| 미제출 | 명단 중 미제출자 |

- 오프라인 발령 프로그램이 이 형식을 그대로 읽게 맞춤(성명 + 생년월일로 연결)

## 8. 화면 · 디자인
- 직원 화면: 모바일 우선, 큰 버튼, 한 화면에 질문 하나, 단계 진행 막대
- 관리자 화면: PC, 표 중심(발령 작업판 W2와 같은 톤 검토)
- 디자인 시안은 이 설계 확정 후 따로 뽑음

## 9. 남은 확인
1. 생년월일 입력 형식: 8자리(19900101)로 할지
2. 성명 + 생년월일이 같은 직원이 있을 때 처리(명단 업로드 때 경고 → 담당자가 개별로 구분값 추가)
3. 희망 사유 구분값 확정
4. 관리자 계정 수(담당자 1명만인지)
