Part 1 · 개념

바이브코딩이란?

단어는 낯설지만, 핵심은 아주 단순합니다.

한 문장 정의

코드를 직접 타이핑하는 대신,
AI에게 우리말로 원하는 걸 설명하면
AI가 대신 만들어 주는 방식.

예전 방식

어떻게 만드는지에 집중
→ 문법·기술을 사람이 익힘

바이브코딩

무엇을 원하는지에 집중
→ 설명은 사람, 구현은 AI

어디서 나온 말?

"코드가 있다는 것조차 잊고,
그냥 vibe(느낌)에 맡긴다."

2025년, AI 연구자 안드레이 카파시가 툭 던진 이 표현이 전 세계로 퍼지며 하나의 흐름이 됐습니다. 이제는 개발자만의 것이 아니에요.

Part 2 · 원리

AI와 대화하는 법

오늘 실습의 성패는 여기서 갈립니다.

핵심 원리

한 번에 완성 X
대화로 가까워지는 것

요청→ 결과→ "이 부분 이렇게"→ 결과→ …
!

완벽한 첫 요청보다, 빠른 두 번째 요청. 안 나와도 정상입니다 — 대화를 이어가세요.

좋은 요청의 레시피

이 4가지만 채우세요

  1. 무엇을 — 만들고 싶은 것 (예: 연차 계산기)
  2. 누가·언제 쓰나 — 맥락 (예: HR 담당자가 입사일을 넣으면)
  3. 어떻게 보이길 — 형태 (예: 웹페이지, 버튼 하나로 깔끔하게)
  4. 예시·규칙 — 구체적 조건 (예: 1년 미만은 매월 1개씩)
같은 목표, 다른 결과

요청이 구체적일수록 결과가 좋아집니다

✕ 막연한 요청

"연차 계산기 만들어줘"

→ 뭘 기준으로? 어떤 화면으로? AI가 추측 → 엉뚱한 결과

✓ 구체적인 요청

"입사일을 넣으면 오늘 기준 연차 일수를 계산해 보여주는 웹페이지를 만들어줘. 1년 미만은 매월 1개씩, 1년 이상은 15개부터. 화면은 깔끔하게 버튼 하나로."

복붙해서 쓰는 마법의 문장

대화를 이어가는 한마디

"좋아, 그런데 OO를 △△로 바꿔줘"

"OO가 이상해. 이렇게 되게 해줘"

"색을 더 차분하게 / 글씨를 크게"

"모바일에서도 잘 보이게 해줘"

"왜 이렇게 했는지 쉽게 설명해줘"

"이거 안전한지 / 문제 없는지 알려줘"

막혔을 때

막히는 건 실패가 아니라 대화의 재료

  • →결과가 이상하면 → 화면에 나온 걸 그대로 복붙하며 "이렇게 나와, 고쳐줘"
  • →뭐가 뭔지 모르면 → "초등학생도 알게 설명해줘"
  • →너무 복잡해지면 → "처음부터 더 간단하게 다시"
